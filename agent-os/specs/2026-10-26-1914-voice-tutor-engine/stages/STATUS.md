## Review efficiency rules

- **Revert checks are saved, not regenerated.** Each stage has a reusable script at `agent-os/review/stage-NN-mutants.mjs` (outside the app code). It applies each revert, runs only the relevant test files, restores and byte-verifies every file, keeps on-disk backups (`--restore`), and takes `--only=<groups>` so each run stays under 10 minutes. It prints only `caught X/Y` plus one line per missed revert.
- **First review of a stage:** write the script and run the full sweep. **Re-reviews:** run the saved script in chunks, plus new reverts for the lines changed in that fix round. Don't rewrite the existing ones; re-anchor any that are SKIPPED.
- **Delegate mechanical, long-output work** (revert sweeps, bundle scans, full test runs) to a subagent on a cheaper model, and bring back only the summary.
- **Keep context small:** tail and grep output, read only changed files or hunks, never print whole test logs.
- **Each stage gets a fresh reviewer session**, which reads `agent-os/review/REVIEWER_HANDOFF.md`, this file and the stage brief first.
- **Headless: no background subagents or jobs; the turn must not end until the review is done.**
- **Pre-review checker (since Stage 8):** a GLM checker (`agent-os/checker/CHECKER.md`) mechanically checks each builder round first. The reviewer sees only rounds that passed, spot-checks 2–3 of the checker's claims, and spends its effort on bugs, revert checks and judgement. See `REVIEWER_HANDOFF.md` §5.
